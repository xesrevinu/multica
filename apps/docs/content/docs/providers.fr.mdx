Multica ne remplace pas l'outil de codage IA que vous utilisez. Un runtime invoque l'outil déjà installé et connecté sur l'ordinateur, puis renvoie la progression et les résultats dans la tâche.

Si vous utilisez déjà l'un de ces outils, vous pouvez généralement le conserver tel quel. Quatre points à prendre en compte pour choisir :

- s'il est déjà installé sur l'ordinateur ;
- quels modèles votre compte peut utiliser ;
- si Multica doit configurer MCP pour lui ;
- quels skills l'équipe souhaite réutiliser.

Les étapes d'installation se trouvent dans [Installer les outils de codage IA](/install-agent-runtime).

## Outils pris en charge

| Outil | Commande détectée | Reprise de session | MCP géré par Multica | Chemin d'injection des skills |
|---|---|---:|---:|---|
| Claude Code | `claude` | ✓ | ✓ | `.claude/skills/` |
| Codex | `codex` | ✓ | ✓ | `$CODEX_HOME/skills/` |
| DeepSeek Harness | `dsh` | ✓ | ✓ | `.dsh/skills/` |
| Grok | `grok` | ✓ | ✓ | `.grok/skills/` |
| OpenCode | `opencode` | ✓ | ✓ | `.opencode/skills/` |
| Pi | `pi` | ✓ | ✓ | `.pi/skills/` |
| Oh-My-Pi | `omp` | ✓ | ✓ | `.omp/skills/` |
| Yielded | `yielded-agent` | ✓ | ✓ | `.agents/skills/` |

« MCP géré par Multica » signifie que vous pouvez définir des serveurs MCP dans la configuration de l'agent et que Multica les transmet à l'outil avant une exécution. Cela ne signifie pas que l'outil n'a aucun autre moyen de configurer MCP.

## Sources des modèles

Lorsque vous créez un agent, la liste des modèles provient du runtime correspondant. Certains outils exposent un ensemble fixe de noms de modèles ; d'autres renvoient les modèles disponibles selon la configuration locale, le compte connecté et les droits d'abonnement.

Si vous ne choisissez pas de modèle, Multica utilise la valeur par défaut de l'outil. Si la liste est vide, vérifiez que le runtime est en ligne et que l'outil est connecté, puis actualisez la liste.

DeepSeek Harness publie son catalogue depuis le runtime (`dsh --profile multica --list-models`). Ses identifiants de modèle ont la forme `provider/model` (par exemple `deepseek-official/deepseek-chat`) : sélectionnez l'identifiant complet dans la liste.

<Callout type="info">
Des outils différents peuvent utiliser des noms de modèles différents. Après un changement d'outil, l'ancienne valeur de modèle est invalide et doit être choisie à nouveau.
</Callout>

## Reprise de session

Les outils marqués ✓ peuvent reprendre une session existante lors d'une exécution ultérieure. La session d'origine doit encore exister, et l'exécution doit être faite par un runtime qui peut y accéder.

Multica conserve l'identifiant de session renvoyé par l'outil. La prochaine fois que le travail continue sur la même tâche, le runtime tente de reprendre cette session ; s'il ne peut pas, il en crée une nouvelle et poursuit. Pi enregistre un chemin de fichier de session local, donc il dépend davantage de l'ordinateur et du fichier d'origine.

Les règles de nouvelle tentative et de reprise de session sont dans [Exécutions](/tasks#manual-retry).

## Configuration MCP

La livraison MCP gérée pour Pi exige Pi 0.99.0 ou une version ultérieure. Les versions plus anciennes de Pi continuent d'exécuter les agents sans configuration MCP.

<Callout type="warning">
Les commandes, arguments et variables d'environnement des serveurs MCP sont enregistrés côté serveur avec la configuration de l'agent. N'y écrivez pas d'identifiants locaux que vous n'avez pas besoin de partager.
</Callout>

## Injection des skills

Avant le début d'une exécution, Multica écrit les skills liés à l'agent dans les chemins du tableau, afin que chaque outil les découvre par son propre mécanisme.

Les skills déjà présents dans le dépôt ne sont jamais écrasés. En cas de collision de nom, Multica utilise un autre nom de répertoire pour la copie injectée ; après l'exécution, il ne nettoie que les fichiers qu'il a créés.

Codex est traité un peu différemment : il utilise un `CODEX_HOME` propre à chaque exécution, donc les skills ne sont jamais écrits dans le répertoire Codex du système.

Pour créer et lier des skills, voir [Skills](/skills).
