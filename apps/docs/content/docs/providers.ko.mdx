Multica는 사용 중인 AI 코딩 도구를 대체하지 않습니다. 런타임이 컴퓨터에 이미 설치되어 로그인된 도구를 호출하고 실행 진행 상황과 결과를 태스크에 기록합니다.

이미 사용 중인 도구가 있다면 보통 그대로 사용할 수 있습니다. 도구를 선택할 때는 다음 네 가지를 판단하세요.

- 컴퓨터에 이미 설치되어 있는가
- 계정에서 어떤 모델을 사용할 수 있는가
- Multica가 MCP를 설정해야 하는가
- 팀에서 어떤 스킬을 재사용해야 하는가

설치 방법은 [AI 코딩 도구 설치](/install-agent-runtime)를 참고하세요.

## 지원 도구

| 도구 | 감지 명령 | 세션 복원 | Multica 관리 MCP | 스킬 주입 경로 |
|---|---|---:|---:|---|
| Claude Code | `claude` | ✓ | ✓ | `.claude/skills/` |
| Codex | `codex` | ✓ | ✓ | `$CODEX_HOME/skills/` |
| DeepSeek Harness | `dsh` | ✓ | ✓ | `.dsh/skills/` |
| Grok | `grok` | ✓ | ✓ | `.grok/skills/` |
| OpenCode | `opencode` | ✓ | ✓ | `.opencode/skills/` |
| Pi | `pi` | ✓ | ✓ | `.pi/skills/` |
| Oh-My-Pi | `omp` | ✓ | ✓ | `.omp/skills/` |
| Yielded | `yielded-agent` | ✓ | ✓ | `.agents/skills/` |

"Multica 관리 MCP"는 에이전트 설정에 MCP 서버를 정의하면 Multica가 실행 전에 그 도구로 전달한다는 뜻입니다. 그 도구에 다른 MCP 설정 방법이 없다는 뜻은 아닙니다.

## 모델 출처

에이전트를 만들 때 모델 목록은 해당 런타임에서 옵니다. 고정된 모델 이름을 제공하는 도구도 있고, 로컬 설정, 로그인한 계정, 구독 권한에 따라 사용 가능한 모델을 돌려주는 도구도 있습니다.

모델을 고르지 않으면 Multica는 그 도구의 기본값을 사용합니다. 목록이 비어 있으면 런타임이 온라인인지, 도구에 로그인되어 있는지 확인한 뒤 모델 목록을 새로고침하세요.

DeepSeek Harness의 모델 카탈로그는 런타임이 직접 제공합니다(`dsh --profile multica --list-models`). 모델 id는 `provider/model` 형식입니다(예: `deepseek-official/deepseek-chat`). 목록에서 전체 id를 선택하세요.

<Callout type="info">
도구마다 모델 이름이 다를 수 있습니다. AI 코딩 도구를 바꾸면 이전 모델 값은 새 도구에서 유효하지 않으므로 다시 선택해야 합니다.
</Callout>

## 세션 복원

✓로 표시된 도구는 이후 실행에서 기존 세션을 이어 갈 수 있습니다. 원래 세션이 남아 있고, 그 세션에 도달할 수 있는 런타임이 실행해야 합니다.

Multica는 도구가 돌려준 세션 식별자를 저장합니다. 같은 태스크에서 작업을 이어 갈 때 런타임은 그 세션 복원을 시도하고, 복원할 수 없으면 새 세션을 만들어 계속합니다. Pi는 로컬 세션 파일 경로를 저장하므로 원래 컴퓨터와 파일에 더 의존합니다.

재시도와 세션 복원 규칙은 [실행](/tasks#manual-retry)을 참고하세요.

## MCP 설정

Pi에 관리형 MCP를 전달하려면 Pi 0.99.0 이상이 필요합니다. 더 오래된 Pi도 MCP가 없는 에이전트는 실행할 수 있습니다.

<Callout type="warning">
MCP 서버의 명령, 인수, 환경 변수는 에이전트 설정과 함께 서버에 저장됩니다. 공유할 필요가 없는 로컬 자격 증명은 설정에 넣지 마세요.
</Callout>

## 스킬 주입 방식

실행이 시작되기 전에 Multica는 에이전트에 연결된 스킬을 위 표의 경로에 써서, 각 도구가 자기 방식으로 찾게 합니다.

저장소에 이미 있는 스킬은 덮어쓰지 않습니다. 이름이 겹치면 Multica는 주입한 복사본에 다른 디렉터리 이름을 씁니다. 실행이 끝난 뒤 정리하는 파일은 직접 만든 파일뿐입니다.

Codex는 실행마다 `CODEX_HOME`을 쓰므로 스킬이 시스템 전역 Codex 디렉터리에 기록되지 않습니다.

스킬을 만들고 연결하는 방법은 [스킬](/skills)을 참고하세요.
