ローカルランタイムは、Multica デーモンと、デーモンが呼び出せる AI コーディングツールの 2 つで構成されます。使用するツールだけをインストールすればよく、すべてをインストールする必要はありません。

## 1. ツールを選ぶ

すでにインストールしてログイン済みのツールには、追加設定は不要です。モデル、MCP、セッション再開、スキルの対応状況はツールごとに異なります。詳しくは [AI コーディングツール比較](/providers)を参照してください。

Multica は現在、次のコマンドを検出します。

| ツール | 検出するコマンド | 公式インストールガイド |
| --- | --- | --- |
| Claude Code | `claude` | [Claude Code クイックスタート](https://code.claude.com/docs/en/quickstart) |
| Codex CLI | `codex` | [Codex CLI](https://developers.openai.com/codex/cli/) |
| DeepSeek Harness | `dsh` | [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) |
| Grok Build | `grok` | [Grok Build クイックスタート](https://docs.x.ai/build/overview) |
| OpenCode | `opencode` | [OpenCode クイックスタート](https://opencode.ai/en/docs) |
| Pi coding agent | `pi` | [Pi coding agent](https://github.com/earendil-works/pi) |
| Oh-My-Pi | `omp` | [Oh-My-Pi インストール](https://omp.sh) |
| Grok Bot | `gbot` | [Grok Build クイックスタート](https://docs.x.ai/build/overview) |
| Yielded | `yielded-agent` | Yielded agent CLI |

ここでの「対応」とは、Multica が該当する CLI を呼び出せるという意味です。そのツールのアカウント、サブスクリプション、モデルの利用枠を Multica が提供するわけではありません。

## 2. ローカル環境でログインする

インストール後、まずターミナルからツールを単独で起動し、各ツールの手順に従ってログインするか、モデルプロバイダーを設定してください。ターミナル上でリクエストを実行できない場合は、デーモンから呼び出しても失敗します。

DeepSeek Harness を使う場合は、Node.js 20+ をインストールして `npm install -g @deepseek-ai/dsh` を実行し、Multica ランタイムプロファイルを追加してください。このバンドルが Multica の利用する `--stdio` プロトコルを提供しており、素の `dsh` だけでは使えない理由でもあります。`MULTICA_DSH_PROFILE_BUNDLE` にインストールするバンドルを設定すればデーモンが追加します。手動で行う場合は `dsh plugin --profile multica add <bundle>` を実行します。`<bundle>` は `dsh plugin` が受け付けるもの、つまり npm のパッケージ名、ディレクトリ、パック済み tarball のいずれかで、Multica 自身のブリッジは [multica-ai/dsh-multica-runtime](https://github.com/multica-ai/dsh-multica-runtime) にあります。これはまだ公開 npm レジストリに公開されていないため（[multica#6936](https://github.com/multica-ai/multica/issues/6936)）、現時点でセルフホストのチームはそのリポジトリからビルドし、変数をビルド出力のディレクトリに向けます。デーモンを動かすマシンとビルドしたマシンが別なら、`npm pack` が生成する tarball を指定してください。ブリッジが公開されれば、パッケージ名を指定するのが最も簡単になります。いずれの場合も、自チームが公開・ビルドしたものを優先してください。この値は追加の確認なしに各デーモンホストの DSH ホームへインストールされるため、素性の分からないサードパーティのパッケージを指定することは利便性の問題ではなくサプライチェーンの判断です。npm パッケージではなく DeepSeek Harness Desktop をインストールした場合、デーモンはそのアプリが生成する CLI シムも、アプリ自身のユーザーデータディレクトリから探します。macOS は `~/Library/Application Support/DSH Desktop`、Windows は `%APPDATA%\DSH Desktop` です。Windows のそれはローミングのアプリケーションデータであり、インストール先ではありません。アプリ自体は Program Files または `%LOCALAPPDATA%\Programs` に入りますが、駆動される CLI はユーザーごとの他の状態と同じ場所に置かれます。これらのパスのバージョン部分は生成された ID なので、デーモンは列挙して最新のものを優先します。PATH に他のものは必要ありません。生成されたシムはアプリ同梱のランタイムを絶対パスで起動します。DSH Desktop が既定以外の場所にある場合は `MULTICA_DSH_PATH` でそのシムを指定してください。デーモンは `dsh --profile multica --probe` が成功した場合のみ DeepSeek Harness を登録し、失敗した場合は `/health` にプロファイルの欠落を報告します。デーモンを起動する前に `DEEPSEEK_API_KEY` を設定（または dsh の設定に保存）してください。

ログイン情報はツールがローカル環境に保存します。Multica が Claude、Codex などの CLI のログイントークンを受け取ることはありません。

<Callout type="info">
Claude Code は 2.0.0 以降、Codex は 0.100.0 以降、Grok は 0.2.89 以降、OpenCode は 1.1.54 以降が必要です。最低バージョンを満たしていない場合、デーモンはそのランタイムを登録しません。
</Callout>

## 3. デーモンからコマンドを見つけられることを確認する

macOS、Linux、WSL では、次を実行します。

```bash
command -v <command>
<command> --version
```

Windows PowerShell では、次を実行します。

```powershell
Get-Command <command>
<command> --version
```

`<command>` は表にあるコマンド名に置き換えてください。たとえば `claude`、`codex`、`grok` です。最初のコマンドで実行ファイルのパスが返れば、検出できています。

ターミナルではツールを見つけられるのに、Desktop やバックグラウンドのデーモンでは見つからない場合、両者が異なる `PATH` を使っていることが一般的な原因です。アプリを再起動するか、対応する `MULTICA_<PROVIDER>_PATH` 環境変数で絶対パスを指定してください。設定の詳細は[環境変数](/environment-variables#デーモン設定)を参照してください。

## 4. 再検出してオンライン状態を確認する

CLI でデーモンを起動します。

```bash
multica daemon start
```

デーモンがすでに実行中の場合は、新しいツールをインストールした後に再起動します。

```bash
multica daemon restart
```

Multica Desktop を使っている場合は、アプリを終了して開き直してください。

次に Multica の**ランタイム**ページを開きます。対象のコンピューターの下にツールが表示され、オンライン状態になっていることを確認してください。これで、エージェントを作成または編集するときにこのランタイムを選択できます。

<Callout type="warning">
デーモンの起動時には、標準対応している CLI が少なくとも 1 つ検出される必要があります。カスタムランタイム設定はデーモンの起動後に同期されるため、ツールが何もないコンピューターで唯一の起動条件として使うことはできません。例外は 1 つだけです。デーモンが DSH ランタイムプロファイルのインストール（`MULTICA_DSH_PROFILE_BUNDLE`）を開始した直後は、ランタイムが 1 つもない状態で起動し、そのインストールが完了した時点で DeepSeek Harness を登録します。そうしないと、プロファイルを必要とする DSH しかないコンピューターではインストールを完了できません。デーモンが完了前に終了し、インストール処理も道連れにしてしまうからです。
</Callout>

## ツールが検出されない場合

次の順番で確認してください。

1. ターミナルからツール自体を実行し、インストールとログインが完了していることを確認します。
2. `command -v` または `Get-Command` で、実際のコマンド名とパスを確認します。
3. `multica daemon logs -f` を実行し、バージョン、パス、認証に関するエラーを確認します。
4. デーモンを再起動し、現在の環境を読み込み直します。
5. **ランタイム**ページに戻り、コンピューターとツールがどちらもオンラインであることを確認します。

ツールがオンラインと表示されているのに実行が失敗する場合は、タスクの実行ログで CLI が返した具体的なエラーを確認するか、[トラブルシューティング](/troubleshooting)を参照してください。
