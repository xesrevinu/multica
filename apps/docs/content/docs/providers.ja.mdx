Multica は、普段使っている AI コーディングツールの代わりになるものではありません。ランタイムがコンピューターにインストール済みでログイン済みのツールを呼び出し、実行の進捗と結果をタスクに書き戻します。

すでにいずれかのツールを使っている場合は、通常そのまま使い続けられます。ツールを選ぶときは、次の 4 点を確認してください。

- コンピューターにすでにインストールされているか
- アカウントでどのモデルを利用できるか
- Multica から MCP を設定する必要があるか
- チームでどのスキルを再利用したいか

インストール方法は [AI コーディングツールをインストールする](/install-agent-runtime)を参照してください。

## 対応ツール

| ツール | 検出コマンド | セッション再開 | Multica 管理の MCP | スキル注入先 |
|---|---|---:|---:|---|
| Claude Code | `claude` | ✓ | ✓ | `.claude/skills/` |
| Codex | `codex` | ✓ | ✓ | `$CODEX_HOME/skills/` |
| DeepSeek Harness | `dsh` | ✓ | ✓ | `.dsh/skills/` |
| Grok | `grok` | ✓ | ✓ | `.grok/skills/` |
| OpenCode | `opencode` | ✓ | ✓ | `.opencode/skills/` |
| Pi | `pi` | ✓ | ✓ | `.pi/skills/` |
| Oh-My-Pi | `omp` | ✓ | ✓ | `.omp/skills/` |
| Yielded | `yielded-agent` | ✓ | ✓ | `.agents/skills/` |

「Multica 管理の MCP」は、エージェント設定で MCP サーバーを定義し、実行前に Multica がツールへ渡すという意味です。そのツールに他の MCP 設定方法がない、という意味ではありません。

## モデルの取得元

エージェントを作成するとき、モデル一覧は対応するランタイムから取得します。固定のモデル名を公開するツールもあれば、ローカル設定、ログイン中のアカウント、サブスクリプションに応じて利用可能なモデルを返すツールもあります。

モデルを選ばない場合、Multica はそのツール自身の既定値を使います。一覧が空のときは、ランタイムがオンラインでツールにログイン済みかを確認してから、モデル一覧を更新してください。

DeepSeek Harness のモデルカタログはランタイム自身が公開します（`dsh --profile multica --list-models`）。モデル id は `provider/model` 形式です（例: `deepseek-official/deepseek-chat`）。一覧から完全な id を選んでください。

<Callout type="info">
ツールによってモデル名は異なります。AI コーディングツールを切り替えると、以前のモデル値は新しいツールでは無効になるため、選び直す必要があります。
</Callout>

## セッション再開

✓ のツールは、後の実行で既存セッションを続行できます。前提は、元のセッションが残っていて、それに到達できるランタイムが実行することです。

Multica はツールが返したセッション識別子を保存します。同じタスクで作業を続けるとき、ランタイムはそのセッションの再開を試み、再開できない場合は新しいセッションを作って続行します。Pi はローカルのセッションファイルパスを保存するため、元のコンピューターとファイルへの依存がより強くなります。

再試行とセッション再開の規則は [実行](/tasks#manual-retry) を参照してください。

## MCP 設定

Pi への管理 MCP 配信には Pi 0.99.0 以降が必要です。それより古い Pi でも、MCP を設定していないエージェントは実行できます。

<Callout type="warning">
MCP サーバーのコマンド、引数、環境変数はエージェント設定とともにサーバー側へ保存されます。共有する必要のないローカル認証情報は設定に書かないでください。
</Callout>

## スキルの注入方法

実行開始前に、Multica はエージェントに紐づいたスキルを上の表のパスへ書き込み、各ツールが自分の仕組みで見つけられるようにします。

リポジトリに既にあるスキルは上書きしません。名前が衝突した場合、Multica は注入したコピーに別のディレクトリ名を使います。実行後に片付けるのは、自分で作ったファイルだけです。

Codex は実行ごとの `CODEX_HOME` を使うため、スキルがシステム共通の Codex ディレクトリへ書き込まれることはありません。

スキルの作成と紐づけは [スキル](/skills) を参照してください。
